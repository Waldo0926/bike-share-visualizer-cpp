# Legacy coursework

This directory preserves the original 2021 coursework submission:
**城市公共自行车运营可视化数据监控系统** ("City Public Bike-Share
Operations Visualisation Monitoring System"), an object-oriented
programming course design built with MFC (Microsoft Foundation Classes)
in Visual Studio 2019.

`mfc_original/` is the complete Visual Studio project as submitted:

- `20200400230-温硕勋Dlg.cpp/.h` — the main dialog, where nearly all of
  the program's logic lives (CSV import, station lookup, statistics,
  map painting, trip animation)
- `20200400230-温硕勋.cpp/.h` — the MFC application class
- `HelpDlg.cpp/.h`, `HelpDig.cpp/.h` — the "usage instructions" dialog
  (note the typo in the second pair's filename, kept as it was)
- `My20200400230.rc`, `resource.h`, `res/` — the resource script holding
  the whole dialog layout, plus the application icon
- `framework.h`, `pch.h/.cpp`, `targetver.h` — the standard MFC
  precompiled-header scaffolding generated by Visual Studio
- `.sln`, `.vcxproj`, `.vcxproj.filters` — the solution and project files
- `map.bmp` — the calibrated Chicago map image. The resource script
  references it as `IDB_BITMAP1 BITMAP "map.bmp"`, i.e. by a path
  relative to the project directory, so it has to sit here for the
  project to build. The same image is also in `../data/` where the
  modern renderer reads it from.
- `Users.csv` — the small sample user list for the user-import feature

Left out: the `.vs/` IDE cache, `Debug/` and `x64/` build output, the
`.aps` resource binary cache and `.vcxproj.user` local settings. None of
those are source.

## Notes

**It only builds on Windows.** This is an MFC/Win32 GUI program, so it
needs Visual Studio with the MFC component and the Windows SDK. It is
deliberately **not** part of this repository's CMake build or CI — it is
kept here as a historical reference so the changes described in
[`../docs/MODERNISATION.md`](../docs/MODERNISATION.md) can be checked
against what they started from.

**The `.rc` and `.rc2` files are UTF-16.** Visual Studio writes resource
scripts in UTF-16LE, which GitHub's web view treats as binary and will
not display inline. They open normally in a local editor or in Visual
Studio. Every other source file here is UTF-8.

**The code is as submitted.** Including the commented-out experiments,
the inconsistent indentation and the bugs — the point of keeping it is
that the modernisation write-up can point at specific lines. Screenshots
of it running are in
[`../docs/screenshots/`](../docs/screenshots/).
